# The Omniscience

> Рабочий стол «второго уровня». Среда поверх среды. **Windows 10 и Linux/X11.**

<img width="1920" height="1080" alt="Screenshot_2026-10-06_16-56-44" src="https://github.com/user-attachments/assets/9ac87f7c-29b1-4afd-a621-2cf99719109f" />

The Omniscience — это оболочка на Electron + React. На Linux/X11 она может работать как самостоятельная сессия с KWin. В Windows приложение использует системные папки, ярлыки меню «Пуск», корзину и приложения Windows; сторонние окна обнаруживаются и управляются через Win32.

В Windows Explorer остаётся системной оболочкой. Omniscience добавляет прямой запуск Electron в автозагрузку текущего пользователя и скрывает штатную панель задач только после успешной регистрации собственной панели как AppBar. При штатном завершении или ошибке панели Explorer показывается снова; вспомогательный Win32-процесс также восстанавливает панель при завершении приложения.

Если на компьютере ещё сохранена прежняя настройка Omniscience в HKLM Winlogon, приложение при следующем запуске восстанавливает исходное значение из `%ProgramData%\The_Omniscience\windows-shell-backup.json` с запросом UAC, затем настраивает обычную автозагрузку. `npm install` не меняет системные настройки, реестр или оболочку.

На Linux/X11 приложение по-прежнему может запускаться из LightDM как отдельная сессия. Поддержка Wayland ограничена.

## Что внутри

- **Своя оконная среда на Electron + React.** Каждое окно — это нативный `WebContentsView` с собственным preload. Не iframe, не `<webview>`, не имитация. Настоящая изолированная страница.

- **KWin как композитор на Linux/X11, но без Plasma.** Мы не пишем свой композитор с нуля — используем `kwin_x11`; Windows-композитором управляет сама Windows.

- **Управление нативными окнами.** На X11 Omniscience видит окна системы через EWMH. В Windows внешний список окон и управление ими работают через Win32; для окон с повышенным уровнем целостности может понадобиться отдельный администраторский helper.

- **Единый TopBar.** Одна компактная полоса сверху содержит:
  - **крестовину управления** активным окном (перетаскивание, 8 направлений ресайза, кнопки окна, поиск/DevTools),
  - **таскбар** — единый список всех окон: своих и нативных,
  - **меню** — приложения, настройки, поиск.
  - В Windows при запуске приложение сначала снимает прежнюю AppBar-регистрацию своей панели, затем регистрирует её на верхнем краю и резервирует место на экране; в режиме Overview резервирование снимается.

- **Overview.** Отдельное полноэкранное окно поверх всего. Открывается по кнопке «Меню», показывает список приложений и настройки. Закрывается по Escape, по крестику или по клику в пустоту. Не мешает панели — она остаётся видимой сверху.

- **Таскбар — единый пульт.** Клик по окну = фокус. Больше ничего. Случайные клики по самим окнам фокус не меняют.

- **Вкладки меню — тоже приложения.** Список приложений, настройки, поиск — всё это `componentapps`, такие же, как любое, что ты напишешь сам.

- **Мост состояний** через IPC: любое приложение может читать state системы и дёргать её экшены. Никаких whitelist'ов и «разрешённых списков» — только то, что ты сам решишь использовать.

- **Встроенная консоль разработчика.** React DevTools и Chromium DevTools можно открыть прямо для любого окна — отдельной кнопкой в крестовине.

- **Окно рабочего стола.** В Windows Explorer остаётся системной оболочкой, а основное окно Omniscience занимает физические границы монитора. Штатная панель задач скрывается только после успешной регистрации собственной панели как AppBar; при ошибке регистрации или завершении приложения Explorer показывается снова.

- **Все новые окна — внутри Omniscience.** Клик по ссылке с `target="_blank"` или `window.open()` из браузерного приложения не создаёт чужое нативное окно, а открывает новое окно Omniscience. Работает как для Яндекс/Google, так и для любого сайта.

- **Рекурсивность.** Omniscience можно запустить как программу **внутри другой сессии Omniscience**. Верхний уровень работает в режиме сессии (`type: 'desktop'`), нижний — как обычное окно. Управление работает на обоих уровнях независимо. Зачем это нужно — никто из нас, если честно, до конца не понимает. Но работает же.

- Несколько рабочих столов, фон на выбор (картинка, видео, iframe, сплошной цвет, свой React-компонент).

## Требования

- **Windows 10** или **Linux с X11**. На Linux для полной сессии нужны `kwin_x11`, `dbus`, `xrandr`, `wmctrl` и `xdotool`.
- **Node.js** для установки зависимостей и запуска.
- macOS не поддерживается.

## Установка и запуск

```bash
cd /путь/к/проекту
npm install
npm start
```

На Windows приложение запускается через автозагрузку текущего пользователя вместе с обычной оболочкой Explorer. После успешной регистрации панели Omniscience штатная панель задач скрывается; при завершении приложения она восстанавливается. На Linux для полноценной сессии по-прежнему требуется ручная настройка X11/KWin; не запускайте Linux-инструкции установки на Windows.

## Как написать своё первое приложение

Создай папку внутри `componentapps/` — например, `componentapps/hello/`. Достаточно двух файлов:

**`componentapps/hello/Index.jsx`** — точка входа:

```jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App.jsx';

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

**`componentapps/hello/App.jsx`** — само приложение:

```jsx
import React from 'react';
import { viewDispatch, useViewSetting } from '@viewRuntime';

export default function App() {
  const desktops = useViewSetting('desktops'); // любой срез системного state

  return (
    <div style={{ color: 'white', padding: 20 }}>
      <h2>Hello, Omniscience</h2>
      <button onClick={() => viewDispatch('openOverview', { desktopId: '...' })}>
        Открыть меню
      </button>
    </div>
  );
}
```

Пересобери проект — приложение появится в списке.

**Что ещё можно положить в папку приложения:**

- `ipc.js` — обработчики `ipcMain.handle(...)`, регистрируются автоматически.
- `preload.js` — мост из main-процесса в твой view.
- `index.html` — если нужен свой HTML вместо автоматически сгенерированного.

Всё, что лежит в папке, собирается как отдельное приложение — Vite подхватит автоматически.

## Производительность

Omniscience **не борется за ресурсы системы**. В типичном сценарии использования:

- **CPU:** почти ноль. Load average при восьми ядрах — около 1.
- **RAM:** сам DE — 2–3 ГБ. Каждое окно — небольшой отдельный процесс. **KWin:** ~200 МБ. Если 3 ГБ для DE кажутся много — что ж, у Chromium своя цена за то, что он открывает тысячу вкладок и не задыхается.

Никаких фоновых демонов, индексаторов, телеметрии и «умных» сервисов. Автозагрузка системы **полностью отключена** — всё, что нужно, запускает скрипт сессии, и ничего лишнего.

## Чего у нас нет и, может, не будет

Этот раздел существует, потому что мы устали от проектов, которые обещают всё на свете. У нас тоже не всё на свете. Вот честный список того, чем мы **не** гордимся:

- **Wayland.** Не поддерживается. Возможно, никогда не будет — управление чужими окнами там устроено принципиально иначе, и переписывать под него всё — это другой проект.

- **macOS.** Не поддерживается. Замена оболочки Windows задаётся пользователем отдельно; `npm install` не меняет её автоматически.

- **Свой композитор.** Мы берём KWin. Пишем оболочку над ним. Гордиться тут особо нечем — но зато работает.

- **Полноценный файловый менеджер.** Есть xterm, есть Monaco, есть Chonky. Файлового менеджера уровня Nautilus/Dolphin нет. Может, будет. Может, нет.

- **Управление звуком.** Не реализовано. Если повезло с драйверами — звук работает. Если нет — `alsamixer` в терминале тебе в помощь.

- **Настройка сети.** Не реализована. `nmcli`, `nmtui`, `wpa_supplicant` — вот твои друзья. Мы честно не хотим лезть в NetworkManager, там и без нас много желающих.

- **Автомонтирование USB.** Не реализовано. `udisksctl` в терминале. По той же причине.

- **Иконки приложений.** Иногда. Если найдём. Если не найдём — будет дефолтная.

- **i18n.** Только русский. Интерфейс на английском выглядит местами смешно, потому что половина строк захардкожена.

- **Собственные приложения «из коробки».** Есть браузер, есть xterm, есть проводник, есть калькулятор. Уровня «Google-экосистемы» тут не будет никогда. И не надо.

- **Обновления через GUI.** Обновляться нужно через `git pull`. Да, это неудобно. Нет, мы не планируем делать auto-updater.

- **Деградация относительно прошлых версий.** Да, есть. Часть функций из v10 не приехала в v11: переключение рабочих столов не доделано до конца, фон перестал запускаться автоматически, ещё несколько вещей по мелочи. Всё это либо вернётся, либо будет выкинуто как ненужное. Мы не обещаем ни первого, ни второго.

- **Стабильность уровня enterprise.** Мы не enterprise. Мы два человека и ИИ-ассистент. Если у тебя что-то упало — присылай лог, разберёмся. Но обещать «5 девяток аптайма» мы не будем, потому что это враньё.

Если чего-то из этого списка тебе критично не хватает — возможно, Omniscience просто не твоя DE. И это нормально. У нас нет амбиций «заменить всем GNOME». У нас есть амбиции «сделать DE, которая работает так, как нам нравится».
